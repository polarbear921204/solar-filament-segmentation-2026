# V11.3 系統設計與方法詳解（報告用）

## 1. 問題與目標

對 GONG H-alpha 全日面 2048×2048 觀測影像執行**太陽暗條的 instance segmentation**。每條 filament 應有自己的二值 mask 與唯一 ID，最後以 COCO compressed RLE counts 字串提交。評估主指標為 Panoptic Quality（PQ），同時懲罰誤檢（FP）、漏檢（FN）及 instance 合併/碎裂。

## 2. 原始資料與防止洩漏

- MAGFiLO 1.0 Kaggle 2026 訓練資料：**707 張實際 H-alpha 影像、1,154 筆 COCO annotation records**；同張實際影像可有多位標註者紀錄。
- Test：**180 張 2048×2048** 原始影像。
- `scripts/make_3fold_split.py` 依 `physical_key` 對 707 張影像做分組，確保同張實際影像的多筆標註紀錄只落在相同 Fold。
- Fold 分布約 236/236/235 張物理影像；各 Fold 都有自己的 train 和 validation patches。
- **OOF 的 PQ**：每筆 COCO record 只給未用該 physical-image 做梯度訓練的對應 Fold 模型推論；**不是三模型 Ensemble 在這些記錄上的 PQ**，因另外兩個模型可能看過該影像。

## 3. Patch 資料建立與標註

- 2048 原圖以 **1024×1024 tile，stride 768** 切成 3×3 = 9 個帶重疊區塊。
- 每條 COCO mask 裁切到 patch；`visible_area >= 16px`，`visible_area / original_area >= 0.02` 才保留。
- 將局部 mask 轉成一個 YOLO Polygon（`mask_to_single_polygon`），座標歸一化至 [0,1]。每條 filament 的 category 固定為 0。
- 變換與 tile 位置會紀錄在對應 fold patch manifest。
- **注意**：Polygon 化可能弱化非常細的多連通結構；這是方法限制，可在報告討論。

## 4. 訓練三個 YOLOv8m-seg

- 預訓練初始權重 `yolov8m-seg.pt`；Fold 0/1/2 seeds 分別為 **42 / 43 / 44**。
- `epochs=60`, `patience=20`, `batch=4`, `imgsz=1024`, `single_cls=True`, `cos_lr=True`, `overlap_mask=False`。
- Augmentation：rotation ±180°, translation 0.03, scale 0.08, vertical/horizontal flips 0.5, HSV V = 0.12；mosaic/mixup 皆為 0。
- 實際訓練環境與更多參數見 `source_environment/fold*_args.yaml`。
- 用各自 Fold internal validation 挑選 `best.pt`。三份 best.pt 的 SHA256 請對照 `model_hashes_from_server.sha256`。

## 5. V4 三模型推論

### A. 每個模型做 Full-disk patch inference

同一張 2048 影像 → 9 個 1024 tiles → YOLO predict `imgsz=1024`, `conf=0.30`, `retina_masks=True`, `max_det=30` → 每個 patch mask 貼回原圖座標。

### B. 跨 patch 合併 `patch_merge.py`

依 score 降序遍歷，若交集 pixels ≥ 32，且 `IoU >= 0.10 OR containment >= 0.45`，則將同一 instance 的 masks 做 union；否則新開一個 instance。每模型先對候選進行 duplicate suppression，最多保留 15 個。

### C. 三模型 instance cluster + voting `ensemble_merge.py`

把 Fold 0、1、2 的 instance masks 依 confidence 分數排序，在**每 cluster 每模型最多只能有一個 instance**的條件下做 greedy matching：

- `match_iou >= 0.25 OR containment >= 0.55`
- `min_intersection >= 32 pixels`
- `min_model_support = 2`
- `pixel_vote_threshold = 0.50`

注意 `pixel_vote_threshold` 的實作是 `vote_count >= max(1, 0.5 * cluster_member_count)`：**2-model cluster → ≥1 票，即 union；3-model cluster → ≥2 票，即 majority**。報告應明白說出，不能誤寫成所有情況都嚴格 2-of-3 像素投票。

### D. 去重 + 互斥 `postprocess.py`

按照信心排序保留最終 instances；以 `duplicate_iou >= 0.80` 或 `duplicate_containment >= 0.88`（兼顧面積比例）移除重複，`max_instances = 15`。已有 mask 占用的像素會從後面的 mask 排除，因此**同張影像最終 masks 不重疊**。

### E. V4 輸出

一個 filament 一筆 CSV row：`filament_id`, `segmentation_rle`。RLE 僅存 compressed counts 字串（2048×2048 大小固定）；V4 baseline 一共 1,130 masks／178 個影像 ID，在 180 張 Test 中有 2 張沒有 mask row。Kaggle Public 0.38。

## 6. V11.3 獨立的 Trim1 邊界修剪（Public 0.39 的新增技術）

**位置**：V4 三模型融合、去重、non-overlap 之後，針對最終 masks 逐條操作。**不使用 GT，不重新訓練，也不會增加新的 instance**。

對原始 BGR H-alpha image 灰階化得到 `I`，計算：

```python
fine = GaussianBlur(gray, sigma=1.0)
coarse = GaussianBlur(gray, sigma=5.0)
dark = coarse - fine
core = erode(mask, elliptical_3x3)
rim = mask & ~core
bright_rim = rim & (dark < -1.5)
if bright_rim.sum() <= 0.15 * mask.sum():
    mask = mask & ~bright_rim
# 若變成空 mask，回退原 mask
```

直覺：`coarse - fine` 在細小的暗條上常為正；對相對局部偏亮的邊界（`dark < -1.5`）做保守刪除。只處理 3×3 eroded border，且總刪除不超過 mask 面積 15%。**此閾值是在開發 OOF 上選定，不能聲稱是無調參的理論最優。**

這個方法只刪除像素，天然不會創造新的 masks 重疊；若 mask 空了則回退。再使用 pycocotools encoding 輸出最終 RLE。

在最終 Test 文件 audit 中：輸入/輸出皆為 **1,130 masks**，改變 **1,124** 條 mask，移除 **168,390 pixels**（原 2,677,672 pixels 的 6.29%），178 張有 predictions 的影像皆有修剪，`number_of_output_overlaps = 0`。輸出 CSV SHA256 = `13c19935e917018fe2a5c550927c2dc1fdf317987be4dba563e22e756d217f8f`。

## 7. PQ 與 OOF 實驗解讀

\[PQ = \frac{\sum_{(g,p)\in TP} IoU(g,p)}{|TP| + 0.5|FP| + 0.5|FN|}.\]

| Fold | Baseline PQ | Trim1 PQ | Delta |
|---|---:|---:|---:|
| 0 | 0.41619 | 0.42169 | +0.00550 |
| 1 | 0.43557 | 0.43693 | +0.00136 |
| 2 | 0.42527 | 0.42909 | +0.00382 |
| **Pooled OOF** | **0.425718** | **0.429275** | **+0.003557** |

Pooled PQ 使用所有 fold 的 TP、FP、FN 和 sum IoU **加總再算**，不是三個 fold PQ 的簡單平均；共 1,154 records／707 physical images。這是單模型 OOF，不是 V11.3 三模型 Ensemble 在本地完整驗證的結果。

Test 的正式對照：原始三模型 Ensemble **Public 0.38** → 同一版本經 Trim1 → **Public 0.39**（由使用者提供 Kaggle 截圖）。Public 四捨五入分數不是 Private LB，亦非準確的相對改善百分比。

## 8. 限制及後續工作

- 存在 multi-annotator labels 不一致；相同實際影像可能有不同 GT records。
- 很細且面積小的 filament 容易漏檢；Trim1 不能找回沒有 instance 的 FN。
- Trim1 在三折 single-model OOF 得到正面提升，但三模型 Ensemble 的本地無洩漏 PQ **尚未建立**。
- 修剪雖提升 Public Score，仍可能對部分 mask 有損，不能保證 Private LB 同幅改善。
- 模型較重（三個 YOLOv8m），推論耗時與 GPU 記憶體量需在實機量測；這份交接包**不捏造速度**。
